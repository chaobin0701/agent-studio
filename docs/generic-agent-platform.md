# 通用 Agent 平台：架构与交付边界

## 定位

**借助 LangChain、Deep Agents、LangGraph 与本地 Phoenix 系统性重构平台，不以旧单 Agent / 客服架构为中心，也不以局部兼容改造为最终交付。**

最新路线以 Deep Agents 负责通用执行、LangChain 负责模型/消息/工具与中间件、LangGraph 负责底层运行与专项图。原自定义通用 Graph 及其节点、状态编码和规划协议已删除，配置/记忆/追踪/评测断言已移至原生执行；不存在新框架外层循环。已完成项、真实验证、风险与后续切换见 [Deep Agents 接入](deep-agents-migration.md)。

旧接口与业务通过边缘适配保留，不要求核心维持不合理的旧抽象。可复用的是权限、工作区隔离、资源发布和审计、已验证的供应商接入、安全传输、文档索引、用量核算；执行器、能力编排、业务状态和后台信息架构可以替换。

当前实现与验收证据见 [迁移记录](langgraph-migration.md)。正式 Run 和所有 Chat 执行路径已使用发布快照与 Deep Agents 单／多 Agent，静态执行回退和旧运行时注册已移除；LLM 已采用成熟供应商 SDK，Skill 辅助资料已接入只读目录，文件产物已支持授权保存、下载和清理。API、网站 Token 和旧 Cookie 真实 HTTP 验证见 [Chat 入口](native-chat-entry.md)。主服务未切换；旧源码/测试参考内核已删除，全部渠道/可选业务扩展、自动埋点和隔离部署仍待完成。本文件不代表整个重构已完成。

## 六个分层

| 层                 | 职责                                                  | 不应承担的职责                         |
| ------------------ | ----------------------------------------------------- | -------------------------------------- |
| 管理控制面         | 工作区、资源、权限、版本、依赖、生命周期、审计        | 执行 Agent 或读取远端工具返回的指令    |
| 准入与快照         | 鉴权、Agent ID 解析、固定发布版本、能力授权、请求限额 | 根据客服关键词指定执行路线             |
| 统一执行服务       | Run 身份、期限、共享预算、子任务隔离、事件与追踪      | 必须依赖会话、网站访客或产品目录       |
| Deep Agents 执行器 | 通用任务、Skills、虚拟文件、上下文与受控成员          | 另套一层自研通用循环、默认越权子 Agent |
| LangGraph 运行层   | 底层图运行、专项路由；持久恢复另行实现                | 数据库业务规则、凭据、产品必填字段     |
| 能力适配层         | 模型、指导加载、任务、Tool、MCP、检索                 | 建立另一套 Agent 循环或叠加重试        |
| 边缘与扩展         | 会话记忆、渠道传输、客服规则、产品卡片、兼容响应      | 成为所有 Agent 的必要依赖              |

`AgentTaskInput` / `AgentFinalOutput` 是通用核心协议。现有 Chat 输入输出只应存在于兼容适配层；无知识库、无 Tool、无客服设置的 Agent 是常规场景，不是特殊旁路。

## 能力模型

### Tool 与 MCP

- Tool 是可执行能力；本地、HTTP、MCP 是来源/传输，不是三个不同的 Agent 执行器。
- MCP 是版本化连接与工具目录。发现仅生成待审核目录，不自动授权新能力。
- 模型只看到当前请求授权的名称、说明和 JSON Schema；连接、凭据、认证头、服务实例留在运行上下文。
- 执行前统一验证作用域、资源状态、参数和预算；调用后产生标准结果、引用与产物。业务字段通过显式扩展投影，不把任意远端正文升格为指令。
- 读写安全策略、幂等性和实际重试由能力执行层负责，图节点 `maxAttempts=1`。不默认并行执行写工具。
- 保留完整调用 ID / 结果配对。需要加载新指导后重新决策时，后续调用明确返回延迟结果，不吞掉批次尾部，也不计入实际调用预算。

上一阶段采用 StateGraph 自定义能力节点验证执行边界。最新路线由 Deep Agents 管理通用循环，LangChain Tool 加平台中间件保留顺序、重新规划和安全重试，不永久维护功能重叠内核。协议适配可换，安全边界不能丢失。[Graph API](https://docs.langchain.com/oss/javascript/langgraph/graph-api)、[工具](https://docs.langchain.com/oss/javascript/langchain/tools)、[MCP](https://docs.langchain.com/oss/javascript/langchain/mcp)。

### Skill

Skill 是可复用指导，不是自动拥有独立模型、记忆或权限的 Agent。

1. **指导加载**：从授权目录按需读取固定版本，更新当前任务上下文，然后让模型重新决策。
2. **辅助资料**：属于 Skill 的版本化只读资源；文本资料管理、完整 JSON 包及按需读取已接入。脚本不能因目录中存在而自动执行，必须另行授权受控能力。见 [Skill 资料](skill-resources.md)。
3. **成员 Agent**：独立的 Agent 发布版本，拥有自己的模型、Prompt 和授权能力，与 Skill 区分。

Skill 的描述与可移植文档负责指导本身；每个 Agent 的挂载配置负责权限。旧文档内的白名单仅作迁移兼容，不作为新的全局授权体系。正式 Deep Agents 不把 Skill 隐式编译成拥有模型/工具的子 Agent，也不继续暴露旧 `run_skill` 任务工具。[Skills](https://docs.langchain.com/oss/javascript/langchain/multi-agent/skills)。

### 知识与业务扩展

知识库是可选能力，全文保底，向量和混合遵循实际索引能力与模型兼容规则。多库独立召回后按排名融合，同配置问题向量复用；不为了图节点划分增加固定大模型调用。

产品、客服规则和卡片格式属于扩展。通用内核输出回答、可选结构化结果、产物和引用；扩展将这些转成旧业务响应。资源恢复与引用可用性验证留在相应适配器，不能通过旧工具正文绕过当前授权。

## 单 Agent / 多 Agent 与版本

- Agent 用稳定 ID 调用，发布版本不可变，每个 Agent 只有一个当前生效版本，不恢复 dev/test/prod 配置入口。
- 默认单 Agent；协作配置属于入口 Agent 的版本，初期是入口到授权成员的星形关系。
- 入口发布时固定成员版本 ID。同一成员只能选择一个发布版本，不选择自身或已经带协作配置的成员。
- 成员的新版本不自动替换既有组合；修改入口配置并发布，才切换成员。
- 成员使用自己的模型、Prompt、Tool/MCP、Skill 和知识库；不默认复制入口的历史、摘要、证据、加载的 Skill 或权限。
- 入口、成员和隔离 Skill 共享次数/Token/期限约束。次数包含实际重试；Token 在调用前保守预留，成功后按实际用量结算，缺失用量的尝试不免费释放。预算估算不替代计费账本。
- 被当前协作引用的历史成员版本仍是有效依赖：成员切换新版本后，其旧模型、工具、Skill、MCP 不能误删；纯向量知识库切换也要检查这些成员。
- 归档入口释放当前协作依赖，历史配置、调用与审计保留；跨工作区复制需复制并重映射成员，不能沿用源工作区的版本 ID。

## 模型、Prompt 和后台

- 模型连接、部署与方案保留清晰职责；请求开始时固定实际方案版本与参数，凭据不进入状态。供应商适配与备用模型可替换，不绑定特定业务。
- Prompt 管理业务指导。运行协议、摘要治理与安全规则属于代码，不依靠用户手工维护内部占位符。
- 新后台以工作区资源与 Agent 为中心，配置按模型与指导、能力、检索、执行与协作分栏；简单字段双列。
- 协作直接选择成员发布版本，展示共享限制与失败策略，不新增一套隐藏的协作环境绑定。
- 执行详情应展示节点、实际尝试、能力版本、兼容回退、用量与失败分类，并提供具备权限的 本地 Phoenix 追踪跳转。未配置追踪时不显示虚构链接。
- 保留旧 web 后台。页面交互由用户验收；开发侧负责真实接口、权限及自动化检查。

## 可观测与部署

- 每次 Run 固定配置与权限快照，关联本地 Run / Trace 与 本地 Phoenix 父子执行树。
- 对自定义模型、Tool/MCP、检索、Skill 和成员显式埋点；图节点可见不等于内部调用自动完整追踪。
- 默认 metadata-only：版本/运行标识、次数、耗时、Token、状态与错误分类。禁用框架环境变量导致的自动全状态上传。
- 导出有采样、有限队列、超时与关闭刷新；本地 Phoenix 不可用不能破坏业务。私有链接不等于公共分享，集中追踪服务不提供本项目的租户隔离，访问需独立平台权限。
- 测试包含无业务依赖、授权失败、版本固定、跨工作区隔离、流式中断、写工具不重放、模型/工具重试和共享预算。
- 隔离 worktree 完成后再交付迁移、环境示例、构建与部署说明；不未经验证替换正在运行的主服务。
