# Agent、Skill、Tool、MCP 生命周期

四类资源统一支持停用、归档、软删除和恢复。正常列表包含已停用资源，默认不展示归档或删除项；新后台通过“已归档”“回收站”切换查看。稳定 Key 保留，不因删除而允许同名资源占用；本期不做永久清理。

## 引用与操作

- 使用中的引用阻止归档和删除，弹窗展示引用名称、状态及 Agent／Skill／Tool 处理入口；接入应用需在接入管理中重新绑定。
- 草稿引用不阻止移除，但提示必须修正依赖才能发布。已删除／归档资源不能继续编辑、测试、发布、克隆、启用、接入绑定或用于新请求。
- 历史引用不阻止移除，不删除原配置、发布版本、历史 Trace 或引用记录。详情和历史只读查看仍可用，Skill 保留只读导出。
- 正常但停用的 Agent 生效配置及 Skill／Tool 发布配置仍保留依赖保护。资源归档／删除后退出当前引用保护。
- MCP 检查正常 Tool 的最新发布配置及被 Agent 生效版本固定的旧 Tool 契约；仅历史 Tool 契约不阻止移除。草稿单独提示，移除后不能绕过发布校验。
- 平台基础工具（search_knowledge、load_skill 等保留名称及其别名实现）不开放移除。

## 恢复与模型清理

恢复只取消归档／删除标记，保持停用。Agent 不恢复原生效指针或接入绑定，需要检查依赖并明确选定生效版本、启用；Skill／Tool／MCP 启用时检查依赖，不自动恢复已移除模型、工具或凭证。

已归档／删除 Agent 的草稿及发布记录只作为模型历史引用，不再阻止模型移除。模型仅有历史引用时沿用模型管理的归档保留规则；其他 Agent、默认模型绑定、知识库或工作区仍在使用的模型继续受保护。恢复 Agent 后，若模型已归档／删除，必须先恢复模型或修改配置才能发布或启用。

## 接口与一致性

资源接口为 `/api/admin/agent-resources`，MCP 为 `/api/admin/external-tools/mcp`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `?state=active/archived/deleted/all` | 列表；默认 active |
| GET | `/:id/references` | 引用检查 |
| POST | `/:id/archive` | 归档 |
| DELETE | `/:id` | 软删除 |
| POST | `/:id/restore` | 恢复为停用状态 |

读操作使用已有查看／管理权限，变更要求 agent_config.manage。所有查询保持工作区隔离。移除、恢复、生效切换、发布、应用绑定及模型变更采用工作区级事务锁协调，服务端在提交前重新检查引用，避免依赖刚发布就被删除。模型／MCP 网络调用不在该锁中执行。每项生命周期变更写入审计。

`0051_resource_lifecycle.sql` 增加归档和删除时间，以及“已移除资源必须停用、Agent 必须清除生效指针”的数据库约束。不改写已有版本或 Trace。页面交互由用户验收，自动化验证覆盖默认隐藏、当前／草稿／历史引用、模型释放、MCP 契约依赖、恢复校验、基础工具保护及历史导出。
