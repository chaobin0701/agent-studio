# 新后台管理与布局约定

本轮以混合用户、独立资源管理和 Agent 工作台为目标，保留旧后台。发布、权限、计费与版本由后端负责，不用隐藏按钮代替安全校验。

## 页面审查与实施顺序

| 模块 | 当前问题 | 目标 |
| --- | --- | --- |
| 导航 | 技术模块平铺，角色和工作区混杂 | Agent、资源、模型、运行记录、设置分组；原 URL 与权限保留 |
| Agent | 长表单、版本选择占主区域、配置与测试分离 | 分组配置、自动草稿和一次发布；试运行跳转独立页面并固定草稿修订 |
| Prompt/Skill/Tool | 保存/验证/发布步骤与历史入口不一致 | 独立编辑、自动草稿、统一状态，历史和 Diff 次级展示 |
| 模型 | 供应商/部署/方案三层反复跳转 | 方案为主、连接配套，保留凭据、诊断与生命周期 |
| 知识库 | 文档操作与配置、历史混杂 | 文档为主，设置/索引历史/回收站分离 |
| 执行/工作区/权限 | 页面标题、操作、留白和密度各异 | 同一列表/详情结构与主题规范 |

## 配置取舍

- 直接展示：资源名称、模型/Prompt、授权能力、知识库、协作成员。
- 条件展示：检索方式/向量模型、成员失败策略、结果与文件能力。
- 运行设置：任务总预算、必要召回参数、网站欢迎语。
- 系统控制：内部检索候选、摘要提示、SDK 重试、文件沙箱及平台安全上限。历史配置不能被页面默默覆盖。
- Agent 只选择独立创建的已发布资源，不内嵌编辑资源正文；成员与资源版本不可静默升级。

## 统一规范

使用 Vben Page/路由/主题、Element Plus 表单、Tabs、Splitter、表格与反馈，不改框架包。页面顺序为标题操作、筛选导航、工作区、分页状态；主操作唯一，危险操作进入更多/设置。8/16/24 间距使用现有主题工具类，简单字段双列，正文/编辑器整行，窄屏单列。短创建/确认用弹窗，持续编辑进入详情。业务弹窗统一使用 Element Plus 原生居中、公开 header/body/footer 类属性与 Teleport；距视口至少 16px，标题和底部操作不随长表单滚动，内容区单独滚动，不再叠加按 vh 设置的内部滚动容器。提示图标放在字段标签内，数字输入与所在列对齐。尽量不嵌套卡片或重复标题；避免三层滚动。表格/编辑器的必要滚动限制在自身区域。

自动保存须显示保存中/失败/冲突、保留在途编辑、阻止覆盖他人修订并提供离开保护。草稿测试固定修订与已发布依赖，仍计入应用额度，不自动批准写工具。发布不等于测试任务完成；知识库上传/索引和供应商凭据不强行采用草稿发布流程。

验收：必要真实接口验证、类型检查与构建；页面交互由用户测试。阶段交付不等于全局重构完成。
