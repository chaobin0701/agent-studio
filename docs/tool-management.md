# HTTP 工具与 MCP 服务管理

## 管理边界

- `search_knowledge`、`load_skill` 由系统代码提供，不出现在工具管理或 Agent 工具选择中。请求自动装配；实际知识库、Skill 权限仍由 Agent 和隔离任务范围限制。
- HTTP 工具通过 Tool 管理创建，内置业务工具只能绑定现有代码实现。
- MCP 连接通过独立 MCP 管理维护，发现工具后显式创建 Tool 草稿。发现、导入、发布、Agent 授权是不同操作。
- 既有进程内 MCP 插件继续兼容；远程接入不修改 `ai/mcp/` 的静态插件边界，适配在 `tool-management/`。

## HTTP 配置

新工具默认为 HTTP：描述、稳定 Key、输入 JSON Schema、URL、方法、认证、参数映射、结果提取、可选输出 Schema、超时、重试和审批。

输入 Schema 支持基础可视化参数表和高级 JSON 编辑；内置/MCP 原生输入契约只读。显式映射支持路径、Query、Header、Body；Body 的目标用点路径表示嵌套对象。路径值编码后替换，不能模板化主机；静态/动态请求头不接受认证字段或 CRLF。

新后台编辑顺序为基本信息 → HTTP 连接 → 输入参数与请求映射 → 返回结果 → 安全与执行策略。参数映射把模型输入转换成接口需要的位置和字段名：例如 `order_id` 映射到路径替换 URL 的 `{order_id}`，映射到 Query 则发送 `?order_id=123`；显式模式只发送已配置映射的参数。

JSON 输入与展示统一复用 CodeMirror 和官方 JSON 语言支持，提供行号、高亮、折叠、主动格式化及语法错误位置提示；错误 JSON 不会覆盖最近的有效配置，并阻止创建、保存、测试或发布。请求头还检查对象结构及字符串值。MCP 契约、工具测试结果及 Agent 验证详情使用只读代码视图；Prompt 变量 JSON 使用相同编辑器。JSON 格式有效不代表满足接口契约，实际 Schema 约束仍由后端验证。

旧配置没有 `mappingMode` 时继续使用兼容行为：GET 参数进入 Query，其他方法发送 JSON Body。旧 `AGENT_TOOL_*` 环境变量凭据仍能读取，非默认工作区要求 `AGENT_TOOL_WS_<id>_*`。

结果提取路径不存在、输出不符合 Schema、HTTP 错误和超时都会直接返回可读失败诊断；错误不当作成功数据。响应最多 1 MiB，Agent 运行时进一步限制结果长度。

## 本应用产品工具

`list_product_categories`、`list_products`、`get_product_detail` 改为统一 HTTP 配置驱动，原专用 Tool 类不再注册。连接来源选择“本应用产品查询接口”，URL 分别为 `/api/tool-services/product-catalog/categories`、`products`、`detail`；输入通过显式 Query 映射发送。详情的 `productId` 与 `productIds` 二选一，批量最多 5 项。

后端按当前 API 端口发起受限 HTTP 请求，自动携带短时且绑定请求的认证令牌，服务端据此恢复工作区，数据库继续执行 RLS。这里只允许三个固定 GET 路径，不允许用户指定宿主、端口、任意后台接口，也不放开通用内网白名单。现有产品上下文投影、规格 revision 与批量查询结果仍保留。

`0050_product_http_tools` 为历史内置资源创建 HTTP 草稿，保留稳定 Key、资源 ID、旧发布内容和 Agent 引用，不覆盖自定义 HTTP 工具。旧内置引用通过 HTTP 兼容适配继续运行；需测试、发布新 Tool 版本并在 Agent 中选择它，配置修改才对该 Agent 生效。新工作区直接使用 HTTP 默认版本。

## 凭证

工具凭证支持 Bearer Token 和自定义 API Key 请求头。使用现有 SecretBox AES-GCM 加密，不回显明文，不写入 Tool/MCP 版本或日志。凭证可轮换与停用，修改要求 revision 乐观锁；引用者使用同一个凭证身份，因此轮换/撤销立即影响后续调用。

凭证目录和连接按工作区 RLS 隔离。复用 `agent_config.read/manage` 权限维护配置，真实工具测试需要 `agent_tools.execute`。MCP 目录获取同时要求配置管理和执行权限。

## MCP

第一版支持官方 SDK 的远程 Streamable HTTP，以及已有进程内插件。支持无认证、Bearer、API Key；暂不提供交互式 OAuth 登录、本地 stdio 命令、Resources/Prompts、Sampling、代码执行或外部 A2A。

流程：创建服务 → 测试连接 → 点击获取工具 → 查看参数和变更 → 创建/更新 Tool 草稿 → 测试/发布 → Agent 选择已发布工具。

连接配置和发现目录保存为不可变版本。连接测试不保存目录；成功获取工具创建新版本，失败保留旧目录。分页发现必须全部完成，并拒绝重复 cursor、重复名称或超过上限的目录，不暴露半个目录。

导入产生确定、无冲突的稳定资源 Key，记录 MCP 原生工具名和连接版本。默认按未知写入能力处理：需要审批、零重试。运营人员可以在核实实际语义后收紧/调整策略，不能改变原生输入/输出契约。

Agent 将 HTTP/内置工具与 MCP 工具分组选择；仍引用同一工具版本集合，更新一组不会取消另一组。没有自动授权新发现工具。

每次 MCP 调用建立受限连接，检查远端当前工具契约后才执行；远端移除或契约变化返回 `mcp_contract_changed`，不会静默跟随新实现。这里固定的是平台契约，不能保证外部服务的代码版本不变。服务禁用和凭证撤销在执行前再次检查。

目前不跨请求缓存 MCP 会话；先保证隔离和契约一致性，后续可引入按工作区/连接版本/认证身份隔离的连接池。

## 网络安全

HTTP 和远程 MCP 共用 `toolFetch`：默认访问公网 HTTPS，拒绝 URL 用户名密码、URL 认证字段、重定向以及私网、回环、链路本地和 IPv4-mapped IPv6。DNS 检查后把已校验地址固定到 socket，避免检查和连接使用不同 DNS 结果。请求最多 1 MiB，底层响应最多 4 MiB。

确有内网或 HTTP 服务需求时，由部署端设置逗号分隔的 `AGENT_TOOL_ALLOWED_HOSTS`，填写精确主机名/IP，不支持用户在页面放开白名单。该配置允许指定主机访问内部网络，必须由部署负责人审核，不要填不受信任域名。

工具结果和 Trace 的常见凭证字段脱敏。系统不会自动下载 MCP 返回的资源链接，也不会执行返回内容里的指令。

## 审批与重试限制

复用现有 ToolExecutionService 和 ToolPolicy。最大重试 3 次表示最多 4 次尝试（含首次），界面明确展示次数。只读/幂等临时错误可重试；MCP 写入工具不支持自动重试。HTTP 写入重试需要服务端真实支持幂等请求头，平台不能仅凭配置保证幂等。

“仅读取，不修改数据”声明实际调用不产生写入副作用，例如查询订单；不是配置编辑锁，也不能替代外部服务的权限约束。创建订单、发消息、删除记录不应开启。当前 HTTP 配置仅 GET 可标记只读；MCP 工具按核实后的真实行为设置。审批由独立开关控制，只读工具也可以要求审批。

敏感工具未批准时返回 `tool_approval_required`，不调用服务。后台真实测试可以由有权限管理员确认并批准本次测试。访客审批交互仍未接入；开启审批的生产写入工具不会被自动放行。测试是实际调用，可能产生业务副作用。

## 迁移及验证

新增 `0047_external_tools.sql`：工具凭证、MCP 服务、不可变连接/目录版本，RLS、跨工作区服务引用约束及运行角色授权。

验证包括：路径/Query/Header/Body 映射、输入注入防护、返回校验、脱敏、审批阻断、DNS/地址和重定向控制、真实 HTTP/MCP 本地服务调用、PostgreSQL 隔离、版本不可变、凭证轮换、导入草稿、真实工具测试/发布和旧 Agent 兼容。

共享服务切换需要先执行该迁移，再重启 API；后台在 8082 保留，旧 web 后台不被替换。页面交互由用户验收。
