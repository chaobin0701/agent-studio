# 知识库管理

## 配置职责

| 位置 | 内容 |
| --- | --- |
| 工作区默认配置 | 已发布的默认向量模型方案，供新知识库预填 |
| 知识库 | 默认文档处理规则、索引模式、实际向量模型方案 |
| Agent 版本 | 知识库范围、检索方式、已发布向量模型方案、返回数量、匹配阈值、上下文字符上限 |

默认向量方案变更不会替换已有知识库。Agent 在向量／混合模式下直接选择已发布向量模型方案，知识库仍独立维护建库所用模型和索引，知识库不再保存独立检索策略。旧 Agent 的历史配置保持不可变；没有指定向量方案的旧发布版本兼容使用知识库索引模型，新的向量／混合草稿必须明确选择方案；缺少检索字段时默认全文、5 条、12000 字；显式自动适配的旧发布版本仍按原策略运行。旧知识库检索配置留作历史数据，不再控制 Agent 查询。

新建知识库默认启用，基本信息弹窗不再展示“允许接入问答”开关。编辑名称、描述不改变已有启用状态；正式检索仍需 Agent 引用该知识库，并通过知识库及文档当前可用状态校验。

详情页使用“知识库设置”入口，在同一弹窗维护基本信息、文档处理和索引设置，事务内统一保存；确认全库重建和归档也在设置弹窗中。关闭有未保存修改的弹窗会提示确认。详情页保留文档、回收站、索引历史和召回测试页签；回收站仅展示已删除资料，提供恢复，不参与正常文档数量统计。

经济模式提供全文索引；向量模式同时提供全文与向量索引，需要已发布的模型方案。普通分块默认 800 字、重叠 60 字；父子分块只展示相关参数。每份文档记录实际处理规则，修改默认值只影响后续上传，重新处理才应用到已有文档。

更换模式或向量模型，先保存待应用设置，再确认全库重建。自动更新继续使用当前生效模式、模型与向量快照，不会顺便应用待确认的变更。

## Agent 检索

新建及编辑 Agent 只提供全文、混合、向量三种检索方式，默认全文。先选择知识库，再展示检索配置，以标准分段切换组件选择方式；未选知识库时不展示检索参数。全文模式兼容所有知识库，不展示或调用 Agent 向量模型。旧发布版本的自动适配仅兼容读取，不作为新配置选项；编辑旧自动适配草稿时改用全文，需明确保存后才生效。

向量／混合模式直接选择当前工作区已发布、启用且未删除／归档的向量模型方案版本。

| Agent 检索方式 | 全文索引 | 向量索引且模型兼容 | 向量索引但模型不兼容 |
| --- | --- | --- | --- |
| 全文 | 全文 | 全文 | 全文 |
| 混合 | 回退全文 | 全文＋向量 | 回退全文并提示 |
| 向量 | 不允许关联 | 向量 | 不允许关联 |

兼容性比较实际向量空间：提供方协议、标准化连接地址、模型标识和维度。相同维度或相同名称不代表兼容；不同方案版本使用相同向量空间时允许复用已有索引。混合检索不兼容时不调用该库模型，也不对其向量进行错误比较；纯向量在保存、验证、发布、历史恢复和请求开始时校验，不悄悄回退全文。

Agent 页面展示当前模型下各库的实际检索能力，混合模式明确显示全文回退，纯向量禁止新增不兼容选择；既有不兼容选择保留供修正或移除。模型与知识库选项可以单独刷新，不覆盖草稿。没有生效索引的库暂不参与混合检索，页面和 Trace 标明未就绪。

Agent 发布并生效后，新请求使用新参数，无需自动重建或修改知识库。选择新模型后，只有显式确认知识库重建才会更换库内索引。

只检索请求快照授权的知识库。各库独立召回，系统控制候选数量，再用基于排名的 RRF 合并，不比较不同检索源的原始分数。最终按 Agent 的数量与上下文上限截取。

同一请求内，显式向量／混合模式用 Agent 固定的模型生成问题向量，在兼容库间复用一次；历史自动适配策略按各库模型配置生成，相同配置复用，可并行处理。缓存不跨请求和工作区。初期没有 LLM 选库或额外 Reranker。

请求固定 Agent 检索策略、允许知识库及索引版本，所选向量模型版本及 composition metadata 进入 Trace；工具执行 Trace 记录每库请求策略、实际策略、回退原因和模型调用数量，仅保留有界脱敏诊断字段，不记录连接凭据。运行时继续检查文档归档、删除、检索启停和知识库状态，历史证据恢复也检查这些条件。

## 上传、自动更新与批量重建

新建知识库在同一弹窗内展示基本信息、文档处理和索引设置，可创建空库，完成后打开上传弹窗。

上传支持拖放或选择多个文件，待上传列表可移除。确认后一次提交同批文件。支持 Markdown、PDF、DOCX，单文件不超过 2 MB，每批最多 20 个文件；格式和大小先在页面校验，再由后端校验原始文件。

流程：上传 → 文档处理 → 自动构建 → 成功后自动启用。每份文档展示上传、处理和失败状态；同批成功文档尽量合并为一次更新，失败文档不阻塞其余成功内容。已有文档处理失败时保留旧索引内容。

自动更新按当前活动版本作为基线，仅替换已处理的待更新文档，未选中文档复制历史分块与向量。选中文档重新构建时，应用当前默认处理规则，再自动更新索引；模型或模式改变则明确确认全库范围。

构建成功前旧版本继续使用。失败记录安全错误，不替换活动版本，可点击重试。队列与数据库状态支持进程重启后的恢复。自动启用不改变知识库原有的问答启停状态。

## 文档状态与回收站

文档处理状态和检索状态分开显示。处理中、失败、待更新、未包含当前版本和已在索引等状态直接展示；其他常驻说明使用可悬停、点击和键盘访问的 Tooltip / Popover。

每份文档只有一个“分块”入口，区分当前检索内容、待生效内容和历史版本。显示首次加入版本及包含它的历史版本。

| 操作 | 行为 |
| --- | --- |
| 停用 | 临时停止召回 |
| 归档 | 保留资料，停止召回 |
| 删除 | 移入回收站，保留原文件、历史分块和引用，支持恢复 |

以上操作立即影响后续检索，不需要重建。恢复时，当前索引已包含文档则直接恢复；未包含则调度自动更新。永久清理留待后续结合保留期限实现。

## 版本与回滚

版本冻结文档内容、实际分块、处理规则与向量配置。回滚不回滚 Agent 策略，也不能绕过归档、删除或停用。

自动策略按回滚后的能力适配；纯向量 Agent 存在索引模式或模型不兼容时阻止切换，并提示关联 Agent；混合 Agent 允许切换并按新版本回退全文。回滚更新知识库的索引代次，已开始的自动构建即使完成也不会覆盖回滚。后续增量以当前版本为基线，未明确重新处理的较新内容不会被悄悄重新加入。

## 接口与迁移

沿用 `/api/admin/knowledge-bases`、工作区隔离和权限。

- `PATCH /api/admin/workspaces/:id/settings`：工作区默认方案；需该工作区的向量管理权限。
- 知识库 `PATCH /:id/processing-config`、`/:id/index-config`：默认处理与待应用索引设置。
- `POST /:id/documents/batch`：multipart `files` 数组，逐文件返回结果。
- `POST /:id/documents/rebuild`：`{documentIds:[...]}`，重新处理所选文档。
- `PATCH /:id/documents/:documentId/delete`、`/restore`：回收站。
- `GET /:id/documents?trash=true`：回收站列表。
- `GET /:id/documents/:documentId/segments`：统一分块、待生效内容、历史版本。
- `POST /:id/versions`：`{activateOnReady:true}`，确认全库重建并自动启用。
- `POST /:id/index-update`：按生效设置重试自动更新。
- `POST /:id/versions/:versionId/activate`：切换／回滚。
- `GET /:id/search`：只读诊断，默认自动适配，不保存策略。

独立 FAQ 管理和接口已移除。迁移 0043 将原 FAQ 转为 Markdown，保留文档 ID、内容、状态和引用，原文在 `inline_content` 中，可下载和重新处理。历史 FAQ 索引兼容读取，不改写旧版本。

迁移 0044 增加默认方案、回收站、处理代次与自动索引状态。模型、索引、文档引用保持工作区隔离。工作区默认保存、构建、切换、回滚、重新处理、删除和恢复都有审计。

页面交互由用户验收；开发验证包括后端测试、隔离 PostgreSQL 回归、新后台类型检查与构建，以及不调用模型的真实经济索引链路。
