# Prompt 管理与发布流程

## 业务提示词与平台模板

普通 Prompt 创建只需要名称，可直接填写正文和描述。稳定 Key 自动生成，也可在高级区域指定；类型由服务端默认处理，历史类型保留，不再作为普通 Prompt 能否被 Agent 选择的依据。

新后台只展示业务提示词，不再提供平台模板分栏及环境切换入口。`agent.planner`、`agent.answer` 和摘要均不在列表中展示；访问旧的内部模板详情链接时只显示提示，不提供编辑界面。内部模板不再参与运行时加载，也不能通过兼容接口编辑、克隆、发布或切换；历史正文、版本和绑定保留，可兼容读取和比较，不改写历史数据。平台 Key 不能被普通创建请求占用。Agent 只能选择已发布、正文不超过 24000 字、不含占位符或必填变量的业务 Prompt。模板变量的完整 Agent 运行时接入不在本次范围内。

当前执行路径：执行协议、工具循环和输出校验由代码维护，业务 Prompt 控制人设、业务要求和回答风格，不改变协议或工具权限。Agent Loop 每轮可以调用工具或返回最终回答；最终回答直接来自该轮模型响应，循环结束后不再通过 `agent.answer` 调用模型重写。未提供业务 Prompt 的兼容路径使用代码内默认配置，不加载 `agent.planner`。摘要继续由代码维护。

## 单循环回答与追溯

- JSON 与 SSE 使用同一个经过协议、结束原因、引用及产品校验的最终结果；会话正文和 Agent transcript 不再保存两份不同的回答。
- SSE 已启用 **生成时实时发送**：从同一模型响应提取顶层 `answer` 片段，立即发送，不等待模型完成或完整校验。不另调模型，不人为增加分段延迟，不把 JSON、工具参数或推理内容作为正文发送。
- 增量字段解码器覆盖跨片段转义、Unicode、字段顺序和嵌套内容。SSE 跟随供应商实际分片即时发送，不把一个 Token 当成一个完整汉字，也不模拟逐字延迟。新增 `answer_reset` 替换临时正文：用于工具决策撤回或最终规范化。引用随 `answer_completed` / `done` 返回；以 `done.answer` 为最终正文。错误或断线保留部分正文并标为未完成，不自动重新生成。
- Trace 记录实际业务 Prompt Key、资源及固定版本，不再将业务 Prompt 伪记为 `agent.planner`；内部协议记录为代码版本 `agent-loop-final-v1`。SSE 回答传输记录为 `live / agent_loop`，非流式结果仍为 `validated / agent_loop`，不再记录不存在的二次回答模型调用。
- 每轮模型请求的主备部署共享最多 4 次实际尝试（首次加最多 3 次重试／回退），请求执行上限为 180 秒。断开 SSE 连接会取消正在进行的执行；循环预算耗尽、协议错误、输出截断、内容过滤和超时作为明确失败返回，不伪装成业务拒答。传输中断不会重新生成回答。
- 工具执行后的下一轮、可选成员 Agent 与摘要任务仍可能各自调用模型；“移除二次回答”不意味着所有问题都只调用一次模型。

## 版本和环境

- 保存草稿只增加修订号，不创建新的版本。
- 编辑已发布版本时准备草稿；已有草稿则优先复用，并明确记录来源版本。
- 发布版本的正文、变量和变更说明不可改写，数据库不可变触发器继续保护历史。
- 新后台不再为业务 Prompt 展示环境发布操作：Prompt 发布可用版本，Agent 选择具体版本并管理实际生效版本；引用和发布审阅展示“当前生效／历史版本”。
- 内部模板历史环境绑定只保留数据，不再参与运行路由。历史业务 Prompt 绑定和旧后台接口保留兼容，不会自动改变 Agent 固定版本引用。
- 回滚业务指导应在 Agent 中选择历史 Prompt 版本并发布，或恢复历史 Agent 版本以更新当前生效指针，而不是覆盖历史 Prompt。

## 发布审阅

`保存并发布`先审阅当前编辑内容，再一次性完成保存和发布。审阅弹窗包含来源版本左右 Diff、变量差异、变更说明和引用该资源的 Agent 版本。首次说明可预填“首次发布”；后续新草稿需要填写具体变更原因。

新后台提交 `expectedRevision` 和 `reviewHash`。保存与发布都锁定草稿行，版本修订变化或审阅内容变化时返回 409，不能把过期审阅覆盖到新的内容上。发布事务写入正文、变量、说明、发布人、发布时间并记录审计。发布不更新 Agent 引用及当前生效指针。

旧后台保存及无请求体发布接口仍可用，但不具备新版客户端的完整显式审阅流程。它们同样增加草稿修订号，以便新版客户端发现变更。

## Diff

使用已安装的 `diff` 生成统一补丁，`diff2html` 展示左右或统一视图。包含原始行号、新增／删除行数、红绿与 `+ / -` 标记、行内变化、同步滚动和展开未修改上下文。正文与变量定义分别比较；发布审阅和独立比较复用同一组件。

无差异时也完整展示两侧正文和行号，增删统计均为 0；两个版本均为空时明确提示。组件按需加载；差异计算设置超时和输入上限，匹配比较次数有限制。HTML 输出经 DOMPurify 净化，模板内容不执行 HTML。配色适配现有 Element Plus 主题。

## 预览与测试

根据变量定义提供字符串、数字、布尔值及对象／数组 JSON 输入，也可使用高级 JSON 输入。支持当前未保存内容预览，不写入任何版本。没有变量时无需提供 `{}`，直接预览正文。

可选变量未提供时替换为空文本；未声明、必填缺失、类型错误直接显示。输出包含行号、字符数和复制操作；正文或输入变更后标记旧结果过期。渲染只做模板替换，不调用大模型；实际回答效果通过 Agent 调试验证。

## API 与迁移

- 新增迁移 `0046_prompt_workflow.sql`：草稿 `revision`、`source_version_id` 和 `published_by`，不改写历史版本正文。
- `POST /api/admin/prompts`：类型和 Key 可省略，支持初始正文。
- `POST /api/admin/prompts/versions/:id/draft`：准备／复用草稿。
- `PATCH /api/admin/prompts/versions/:id`：保存草稿，新后台携带 `expectedRevision`。
- `POST /api/admin/prompts/:id/preview`：`{template,variables,values}`，只读预览。
- `POST /api/admin/prompts/versions/:id/review`：`{template,variables,expectedRevision}`。
- `POST /api/admin/prompts/versions/:id/publish`：上述内容加 `reviewHash`、`changeNote`，事务内保存并发布。
- `GET /api/admin/prompts/:id/usage`：Agent 版本引用及环境。
- 原渲染、Diff、克隆、环境绑定接口保留兼容。

已在隔离、最终回滚的 PostgreSQL schema 中验证迁移和流程。2026-10-13 经用户确认，共享开发库已执行 `0046_prompt_workflow` 并重启 API；真实接口验证列表、详情、引用查询、修订号及未保存内容预览，确认预览不改写版本、缺失必填变量返回 400。未执行并行开发中的 `0047_external_tools`，未重启 Worker 或旧后台；页面交互由用户验收。
