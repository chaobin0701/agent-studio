# 工作空间与运行配置

管理端通过 X-Workspace-ID 明确空间，服务端检查成员资格、空间状态及业务权限。所有者／管理者具备空间业务权限，读者只有读取权限，自定义成员使用所授权限；账号和角色管理仍由平台权限控制。未选空间的 auth/me 可读取平台身份，用于选择或创建空间。

SQL 和 Drizzle 使用同一非所有者角色 agent_studio_workspace_runtime，通过 app.workspace_id 与 RLS 限定配置、文档、索引、会话、额度和日志。即使连接账号是超级用户，业务查询也先 SET ROLE；连接返回池前重置角色和空间。账号生命周期及可信接入应用发现使用单独平台入口，业务查询不能绕过隔离。数据库连接用户须可 SET ROLE；迁移用户须有创建／授权角色权限。

0039 将已有数据和成员迁到默认空间；0040 增加每个 Agent 独立的环境绑定；0041 校验跨空间外键、JSON 配置引用和无密钥副本；0042 允许内置应用在首次启动时等待默认 Agent 初始化。升级执行 npm run db:migrate 后重新构建并重启 API 和 Worker。默认空间保留环境变量凭据兼容；其他空间供应商需独立凭据，REST 工具密钥使用 AGENT_TOOL_WS_{workspaceId}_ 前缀。

请求开始在 repeatable-read 事务中固定 Agent、业务 Prompt、模型方案、Skill、Tool 和知识范围。Agent 必须配置模型方案，不隐式使用全局默认模型。异步文档任务记录 workspaceId，Worker 恢复空间；新上传文件使用空间子目录，旧文件仅默认空间可访问。

跨空间复制只复制所选配置及必要依赖，并在目标空间创建独立草稿，不复制密钥、环境发布、接入应用、文件、会话或业务日志。模型供应商副本停用，需重新配置凭据；知识库不带数据和索引。源／目标分别检查依赖读取／创建权限，LLM 与向量权限独立。

验收：server/test/workspace-postgres.test.mjs 使用独立 schema 和真实运行角色，验证同 Key 跨空间共存、成员权限、RLS、外键和 JSON 越界拒绝、独立 Agent 快照、发布后旧快照不变、配置副本与文件路径隔离。设置 KB_INTEGRATION=1 与数据库配置运行；测试结束删除隔离 schema。
