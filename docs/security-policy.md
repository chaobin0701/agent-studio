# 统一安全策略（第四阶段）

本文档定义 agent-studio 当前服务的安全边界。它是实现和验收的基准，不是对外暴露的 API 文档。

## 边界

- 管理后台 API 需要管理员 JWT 和细粒度权限；访客聊天只以浏览器会话隔离，不把访客会话当作身份认证。
- 资料上传、重处理、归档和管理员管理属于状态变更操作，必须经过管理员认证、权限校验和审计记录。
- Agent、Tool 和 Provider 只能使用已注册的能力。模型输出的工具名、参数、引用和外部响应都必须在边缘校验。
- 外部模型、Embedding 服务和数据库凭据只来自环境变量，日志和错误响应不得回显密钥、Token、密码、完整提示词或上传内容。

## 配置

- `JWT_SECRET` 至少 32 字节；JWT 显式包含 issuer、audience 和过期时间。
- `DATABASE_URL`、`UPLOAD_ROOT`、`TRUST_PROXY`、Origin 白名单和限流参数由 `AppConfigService` 统一读取。
- 生产环境不使用隐式默认密钥。空的 `LLM_API_KEY` 只允许在词法检索或本地测试场景下启动。

## 请求安全

- 全局 DTO 白名单和禁止未知字段。
- 管理员登录、访客聊天和文件上传分别限流，并限制并发量、请求体大小和 multipart 文件数量。
- 管理员 JWT 使用 Http Authorization Bearer 头；浏览器访客会话使用 HttpOnly、SameSite Cookie。
- 状态变更请求只接受配置的 Origin；不把 `X-Forwarded-For` 当作可信身份，代理跳数必须显式配置。

## 文件和工具

- 仅接受 Markdown、DOCX、可选文字 PDF；扩展名、大小、文件头、文本编码和解压/解析资源都要校验。
- 文件以随机 storage key 存储，数据库记录和队列任务在同一事务边界内创建；资料目录不允许通过用户输入拼接路径。
- Tool 采用最小权限和固定 JSON Schema；禁止模型动态注册工具、访问数据库或执行任意网络请求。

## 错误、日志和审计

- 对外错误统一返回稳定错误码、消息和 `requestId`；内部堆栈只写服务端日志。
- 请求日志只记录方法、路径、状态、耗时、requestId 和匿名主体标识，不记录 Authorization、Cookie、密码、Token、完整请求体或模型提示词。
- 管理员的资料和权限变更写入审计日志；审计详情使用白名单字段并脱敏。

## 验收

验收至少覆盖：未认证/无权限、错误 Origin、重复登录限流、越界上传、非法工具参数、Provider 超时和错误响应脱敏；同时确认健康检查、登录、资料处理和聊天主流程继续可用。
