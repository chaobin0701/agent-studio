# 新后台开发约定

本文件适用于 `admin-vben/` 及其子目录。该项目基于 vue-vben-admin 的 Element Plus 版本，作为 Agent Studio 唯一管理后台维护。

## 开发目标

以快速、稳定实现业务功能为目标。尽可能使用后台框架提供的组件、布局和功能，保持统一的样式与交互。复用成熟方案是默认选择，自行实现必须有明确的必要性。

## 方案选择顺序

1. 优先使用本项目已有的 Vben 布局、组件、适配器和功能。
2. Vben 未覆盖时，使用 Element Plus 的标准组件与交互。
3. 复杂能力优先使用项目已安装的成熟功能库；现有依赖无法满足时，评估维护活跃、兼容当前技术栈的成熟库。
4. 以上方案确实无法满足业务要求时，才做最小范围的自定义实现，并在交付说明中交代原因。

实施前先检查本地已有能力和对应版本的官方文档、示例。不要因为不熟悉现成组件，就直接重写相同功能；也不要复制与当前版本不兼容的接口。

## 页面与功能的复用方式

| 场景 | 默认方案 |
| --- | --- |
| 后台整体结构 | Vben 的布局、侧边导航、顶栏、面包屑、页签和路由机制 |
| 列表、筛选、分页 | Vben 已有表格适配与筛选方案；适合简单场景时使用 Element Plus 表格和分页 |
| 新建、编辑、表单校验 | Vben 表单及组件适配器，结合 Element Plus 标准输入组件 |
| 弹窗、抽屉、确认操作 | Vben 的弹窗、抽屉方案及 Element Plus 的确认组件 |
| 下拉选择、输入过滤、多选 | Element Plus 已有选择组件，通过其配置满足需求 |
| 消息、加载、空状态、错误状态 | Vben 或 Element Plus 的现成组件，统一使用方式 |
| 权限、主题、国际化、状态管理 | Vben 已有机制和项目已建立的适配层 |
| 上传、编辑器、图表等复杂能力 | 优先复用已有集成，其次选用成熟功能库 |

这些约定用于选择合适的现成方案，不要求为了统一而给简单页面增加不必要的复杂度。

## 样式与交互

- 使用 Vben 和 Element Plus 的主题、设计变量及标准布局方式，保持字体、颜色、间距、按钮和反馈一致。
- 优先通过组件属性、插槽、主题配置完成调整。局部布局可以使用项目已有的工具类或少量 scoped 样式。
- 不自行重写按钮、输入框、选择器、表格、分页、弹窗等基础控件，也不建立第二套基础 UI 体系。
- 不为每个业务页面单独设计一套视觉风格；相同场景沿用相同的布局和操作方式。
- 避免大量硬编码颜色与尺寸、全局 CSS 覆盖、`!important` 和依赖组件内部 DOM 的样式补丁。
- 共性的样式调整集中维护，业务页面主要负责数据和业务流程。

## 代码与依赖

- 页面负责组合现有组件、配置和业务逻辑。重复出现的业务能力可以做薄封装，避免复制粘贴或重新包装出另一套框架。
- 请求、认证、权限和状态管理沿用已有适配层，不在各页面重复实现。
- 默认通过应用层配置与适配接入功能；直接修改复制的 Vben 框架包应有明确必要性，并记录差异，便于后续升级。
- 新增依赖前检查已有依赖是否满足需求，避免引入功能重叠的组件库或功能库。确认许可证、维护状态及 Vue、Vite、Element Plus 版本兼容性。
- 后端接口尚未稳定的功能先定义清楚适配边界，避免为暂时的接口差异构建大量自定义 UI。

## 交付检查

- 说明复用了哪些现成能力；如有自定义实现，说明现成方案无法满足的具体需求。
- 确认新页面与已有页面的主题、布局和交互一致，并检查加载、空数据、错误、权限不足等实际状态。
- 代码变更运行 `pnpm typecheck` 和 `pnpm build`；涉及页面交互时，按变更范围检查浏览器行为。
- 当前目录是 Agent Studio 唯一管理后台；不要重新引入旧后台或业务官网。
