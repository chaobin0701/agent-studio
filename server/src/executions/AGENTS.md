# Generic Run entry

Run admission is an edge over the existing IntegrationService authority, not a new quota, credential or execution engine. Pin the app-authorized Agent composition before execution; the public body cannot choose system/tool messages, credentials, Prompt/model versions or larger published limits. Only platform API keys may use this stateless entry. Keep old Chat endpoints and their fingerprints/results compatible.

The separate administrative preview uses AdminAuthGuard and explicit workspace configuration/execution permissions, a selected application and published Agent snapshot or an explicitly selected draft revision of that same Agent. Only the preview entry may compile a draft; dependencies/members stay published, all validation applies, and no version is activated. Include the draft revision in the fingerprint, reject stale preflight state and caller-supplied identity. It shares AgentRunService execution/persistence and IntegrationService admission/accounting, with an independent administrator ownership/idempotency namespace, never fabricated API-key/visitor credentials. Preview is an independent task, not an implicit conversation or draft publication.

Do not create implicit conversations, summarize caller-supplied history, load caller URLs/paths, or accept fabricated tool results. Document attachments resolve only from the entry Agent's authorized libraries and pinned index versions, rechecking current document availability. Children never inherit caller history or attachments. Use the same AgentExecutionService/Deep Agents for all members; Skills are readonly published resources, not implicit child loops. Selected file outputs use the separate controlled artifact service; do not serialize their bytes into Trace or public output.

The integration call ID is the Run ID; the existing model-attempt ledger owns billing and request idempotency. The nullable-conversation local Trace stores diagnostic state with the existing debug/read permissions; public JSON/SSE and replay expose only the canonical output, IDs and ledger usage, never that state. A failed/expired request must not restart itself or replay write tools.

Explicit single-Agent human interactions use the native LangGraph checkpointer and Command resume through interactions/. Only a trusted host may construct this state; public replies cannot replace tool arguments, grants, checkpoints or pinned configuration. Pausing atomically records the card and releases the execution slot while retaining the original ledger. Resuming revalidates current identity, resource availability, quotas and the original published snapshot. Waiting is not completion or failure. This is not automatic crash recovery: unknown writes, failed runs and expired checkpoints must never replay. Administrative draft preview and nested member interactions remain unsupported and fail closed.
