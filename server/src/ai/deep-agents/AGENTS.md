# Managed Deep Agents integration

Deep Agents owns the general model/tool loop for formal Run and all Chat execution. Each entry requires a published Agent snapshot; missing wiring/configuration fails closed without static defaults or legacy fallback. The old general kernel and its historical execution fixtures have been deleted. Do not wrap this harness in a custom decision loop, restore a legacy fallback or add an implicit Skill Agent. Deterministic specialized flows use a separate explicit governed LangGraph interface, not a second general-purpose loop.

PlatformChatModel is a governed LangChain facade over LlmService, whose suppliers now use the mature ChatOpenAI SDK rather than a parallel hand-written HTTP/SSE engine. LlmService remains the single retry/fallback/accounting authority. Model, summary and member calls must share the same platform budget. No SDK retry middleware, hidden default model, cloud tracing, prompt/body export or uncontrolled structured-output repair call.

All platform Tool/MCP execution goes through ToolExecutionService using the fixed runtime scope. Framework filesystem tools are restricted to a bounded Run-local StateBackend. Published Skills are immutable virtual files, not host paths; no FilesystemBackend, shell, execute tool, long-term store or implicit general-purpose subagent. Framework default tools are not an authorization grant. Reject hostile glob patterns before the framework matcher runs.

Only platform-resolved input/configuration may construct the harness. HTTP authentication, snapshot resolution, persistence, quotas and artifact downloads remain outside it. Do not advertise code-path migration as production deployment; main services have not switched. Chat history never replays old tool bodies or parent state. Mount only bounded host-validated context, recheck resource availability when actually reading, and never inherit root context/files into members. Page interaction is tested by the user.
