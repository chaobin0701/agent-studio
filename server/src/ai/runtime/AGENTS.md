# Platform capability adapters

This directory contains platform capability/output contracts and the unified execution facade. Every formal Chat/Run uses a published snapshot and ../deep-agents/. The old adapters/nodes, recursive task host and custom state codecs are deleted: no own planning loop, static fallback or second fixed answer-model call. Data contracts are JSON-only; live execution objects must not be serialized or reconstructed from untrusted collection-shaped arguments.

Business capabilities live outside this platform and connect through ordinary HTTP/MCP tools; never add business rules to platform contracts. During migration, preserve native call IDs, ordered complete tool batches, deferred results, context budgets, cancellation, resource freshness, permissions and retry/accounting ownership. Existing Chat payloads remain supported through this adapter; new generic capability tests must not require products, a knowledge base or customer-service setup.

Chat input/result types live here (platform-input/platform-result). capability-output accepts only explicitly declared, bounded and redacted JSON artifacts/references, resolving final IDs against successful authorized outputs. Never infer artifacts from arbitrary Tool.data, attach fabricated files, replay writes on projection failure or place an old Chat envelope in generic structured data. Native SDK task middleware owns member execution and shared budgets; HTTP Orchestrators must not regain recursion.

Public artifacts/references are generic explicit capability outputs, not business-specific renderers or mandatory collections. No hidden permission inheritance. Trusted idempotent read caching stays request-local and may not bypass schema/permission checks or cache writes/approval operations.

TaskExecutionResult is the canonical native result: it must not acquire ChatAnswer, product cards, public conversation transcripts or legacy result envelopes. The explicit chat/agent-chat-adapter projects the existing Chat API over runTask; it does not execute another model or tool. Capability context contributions come from the gateway once, not concrete tool-class detection or a second payload projector.

The legacy recursive task host has been deleted. Native SDK member orchestration owns published continue/fail policies, shared budgets and parent cancellation. Skills never create implicit isolated Agents. Actual successful context projections come from ToolExecutionOutcome.contextResources; do not invoke the projector twice or infer resources from arbitrary data. Native business renderers are edge-only and cannot grant tools, inherit parent/member histories or mount another Agent's files. Decisions and tool attempts have independent limits: never restore the old maxPlannerRounds > maxToolCalls rule.
